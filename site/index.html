How mr-ducksafe works

Scan & match

Knows exactly what is installed

  • Reads name, version and publisher from the Windows Registry Uninstall keys
  • Maps each program to an official CPE identifier with 50 curated mappings
  • Lists anything it could not recognise with --show-unmatched

NVD query

Official CVE data for your exact version

  • Queries the NVD CVE API 2.0 — the right source for desktop software
  • Compares each CVE's affected version range with what you have installed
  • Only anonymous {vendor, product, version} leaves your machine

Single binary

One .exe — no installer, no runtime, no account.

Local history

Every scan is saved to SQLite; history and prune manage it.

Zero telemetry

No machine name, user or IP is ever sent. Results stay in ~/.mr-ducksafe.

Built for your terminal and your pipeline

Fail a build when findings cross your threshold, keep the JSON report as an artifact, and read the same results as a table at your desk.

# high+ finding → exit 1 → pipeline 'failed'
name: cve-scan
on:
  schedule: [{ cron: "0 6 * * 1" }]
jobs:
  scan:
    runs-on: windows-latest
    steps:
      - uses: actions/setup-go@v5
        with: { go-version: "1.25" }
      - run: go install github.com/yemresalcan/mr-ducksafe/cmd/mr-ducksafe@latest
      - run: mr-ducksafe scan --fail-on=high --format=json -o report.json
        env:
          NVD_API_KEY: ${{ secrets.NVD_API_KEY }}
      - uses: actions/upload-artifact@v4
        if: always()
        with: { name: cve-report, path: report.json }

Why mr-ducksafe?

The Adobe Acrobat, Chrome, Office and Java on your machine — their old versions carry serious, publicly known vulnerabilities.

Nobody wants to track them by hand, and a 500-row CVE list does not tell you what to do next.

mr-ducksafe does the tracking for you, locally, and answers the only question that matters: what should I update first, and how?
