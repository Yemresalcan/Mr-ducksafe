Features

Small tool, sharp focus

Built for people who want an answer, not a 500-row spreadsheet.

Single binary

One .exe. No installer, no runtime, no account, no admin rights needed to scan.

Official NVD data

CPE-based lookups against NVD CVE API 2.0 with version-range matching — the right source for desktop software.

Plain-language risk

“The application can be hijacked through a memory error” instead of a wall of CVE summaries.

Fix in one command

A winget upgrade command or update link for every finding, grouped per application.

Local history

Every scan is saved to SQLite. history lists past runs, prune cleans them up.

CI-friendly output

--format=json or markdown, --output FILE, --fail-on=high and NO_COLOR support.

CI/CD

Fail the pipeline, not the audit

Run it on a schedule or on self-hosted Windows runners. When findings cross your threshold, the exit code turns the job red and the JSON report is kept as an artifact.

.github/workflows/cve-scan.yml
name: cve-scan
on:
  schedule: [{ cron: "0 6 * * 1" }]
jobs:
  scan:
    runs-on: windows-latest
    steps:
      - uses: actions/setup-go@v5
        with: { go-version: "1.25" }
      - run: go install github.com/yemresalcan/mr-ducksafe/cmd/mr-ducksafe@latest
      - run: mr-ducksafe scan --fail-on=high --format=json -o report.json
        env:
          NVD_API_KEY: ${{ secrets.NVD_API_KEY }}
      - uses: actions/upload-artifact@v4
        if: always()
        with: { name: cve-report, path: report.json }
Privacy first

Your inventory stays on your machine

Fully local scan

The registry is read locally. Nothing about your machine is uploaded.

Minimal lookups

NVD only ever sees anonymous {vendor, product, version} queries over HTTPS.

No identifiers

No machine name, user name or IP-derived data is sent anywhere.

Zero telemetry

Results live in a local SQLite file at ~/.mr-ducksafe. Delete it any time.

FAQ

Questions, answered

Which applications does it cover?

50 popular Windows apps today — browsers, Office and PDF readers, developer tools, remote-access and media apps. The list lives in mappings.yaml and grows through community pull requests; --show-unmatched shows what was not recognised.

Why is my scan slow?

Without NVD_API_KEY, NVD allows 5 requests per 30 seconds. A free key raises that to 50, so a typical scan drops from about two minutes to around 15 seconds.

Does it work on Linux or macOS?

Binaries are published for all three, but the software scanner reads the Windows Registry only for now. dpkg/rpm and Homebrew support are planned for v0.2.

Windows SmartScreen warns me about the .exe.

Release binaries are not code-signed yet. Verify the zip against checksums.txt from the release, then choose “More info → Run anyway”.

Some CVEs look very old (2008, 2012…).

NVD flags some protocol-level issues (TLS, SPDY…) for every version of a product. The summary groups them; --details shows the raw list.

Is it really free?

Yes — MIT licensed, no account, no paid tier. Issues and mapping PRs are welcome on GitHub.
